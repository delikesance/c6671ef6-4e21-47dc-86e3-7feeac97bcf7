## Chantier 3 — Serveurs : refresh au chargement, puis cache jusqu'au redémarrage + cache d'images

### État actuel (vérifié)
- `packages/app/lib/features/home/presentation/guild_avatar.dart` :
  - `GuildDirectory` = cache mémoire **TTL 30 min** + dédoublonnage in-flight + file séquentielle ; alimenté par `GET /users/@me/guilds` avec le token du bot (stockage sécurisé) ;
  - `GuildAvatarStrip` : source 1 = **cache du gateway** (`gateway.guilds.cache`, synchrone, gratuit), source 2 = REST, sinon repli neutre (icône serveur) ;
  - `HomeBotAvatar` (`home_ui.dart:87`) : `Image.network(...)` + `gaplessPlayback` + `loadingBuilder` → repli pendant le chargement, `errorBuilder` → repli. **Pas de cache disque** : dépend du `PaintingBinding.instance.imageCache` (mémoire, configuré `main.dart:140`), évincé/vidé au redémarrage ⇒ **re-fetch HTTP** des icônes.
- `packages/app/lib/features/bot_editor/presentation/screens/bot_sub_pages/guilds.page.dart` : page « Serveurs » = **REST direct à chaque montage** (`_loading` + client NyxxRest créé pour la page) ⇒ requête à chaque visite, **aucune réutilisation** du cache de la carte Home.
- Dépendances : `path_provider` ✔, `sqflite`/`sqlite3` ✔, **pas** de `flutter_cache_manager` ni `cached_network_image`.

### Approche
1. **Source unique de vérité par session** : faire de `GuildDirectory` le **cache session** (chargement unique, **pas d'expiration**, invalidé au redémarrage de l'app), exposant un `ChangeNotifier`/`ValueListenable<GuildsState{loading,data,error}>`.
   - Chargement **au démarrage** (throttlé par la file existante, N bots) OU au premier accès avec état `loading` explicite → pas de re-fetch au retour sur la Home.
   - **Refresh manuel** conservé (bouton « Actualiser » sur la page Serveurs + « Réessayer » sur la carte) = seule façon de forcer un GET après le premier.
2. **`GuildsPage` consomme `GuildDirectory`** (plus de `NyxxRest` local) : affichage immédiat si cache chaud, spinner seulement au premier chargement ; « Quitter le serveur » continue de fonctionner (invalider l'entrée du bot après l'action).
3. **Cache d'images sur disque** (le point « éviter de call des images via HTTP ») :
   - option A (recommandée) : `flutter_cache_manager` (nouvelle dep) → `CachedNetworkImage`-like via `ImageProvider` du cache manager, `stalePeriod: 30 j`, `maxNrOfCacheObjects` borné, clé = URL CDN `size=128` ;
   - option B (sans dep) : petit `ImageDiskCache` maison (`path_provider` + fichier `.img` par hash d'URL + `MemoryImage`/`Image.file`), TTL long.
   - Les icônes de serveurs bougent rarement (hash dans l'URL) ⇒ cache long = sûr. À appliquer à `HomeBotAvatar` (donc carte Home, strip de serveurs, page Serveurs, avatars de la page éditeur `home.ui.part.dart:138`).
4. **États visibles** : « chargement » = repli/skeleton (jamais de spinner bloquant), erreur réseau silencieuse → repli neutre (comportement existant conservé et testé).

### Fichiers

## Chantier 5 — Alias de commandes (plusieurs mots déclencheurs)

### État actuel (vérifié) — précision importante
Le user pense que « c'est supporté par `packages/runner` » : **à moitié vrai**.
- Le **conteneur** de config est opaque : `BotConfig.commands` = `List<Map<String, dynamic>>` (`packages/shared/lib/bot/bot_config.dart:167`, `toJson` l.326) ⇒ **un champ `data.aliases` traversera l'app → payload (`buildBotPayload`) → R2/MinIO → runner sans aucun changement de schéma**. C'est la partie « supportée ».
- En revanche **le matching n'existe pas** : `packages/shared/lib/engine/event_dispatcher.dart`, `_tryHandleLegacyCommand` (l.627-680) matche **un seul nom** : `cleanName == commandName || rawName.toLowerCase() == commandName`, avec `cleanCommandTriggerName` (l.1240) qui retire les marqueurs `{$t...}` (déclencheurs temporisés) ; `extractTimedTriggerDelay` (l.1247) gère le délai.
- Côté app : `legacyModeEnabled` / `legacyPrefixOverride` / `legacyResponseTarget` sont normalisés en **allow-list** (`logic/normalize_command_data.dart:126-134` puis l.205-215) → **un champ non déclaré est supprimé à la sauvegarde** (l'alias doit donc être ajouté là en priorité).
- Le nom effectif d'une commande legacy = `legacyPrefixOverride` sinon `name` (`normalize_command_data.dart:22-24`).
- Le runner ne fait que décider du mode d'écoute (`runner_runtime_controller.dart:881 isLegacyCommandEnabledInConfigEntry`) et exécute le moteur partagé → **aucun changement de contrat runner/R2**, mais **des tests** côté runner pour verrouiller la non-régression.
- Le bloc « Quand est-ce que cette commande se lance ? » = `scratch_blocks/entry_point_block.dart` (sections Slash/Prefix/User/Message + config legacy dépliable : switch `legacyModeEnabled`, champ `legacyPrefixOverride`, `legacyResponseTarget`).

### Approche
1. **Données** (`data.aliases: List<String>`) :
   - normalisation : trim, **minuscules**, sans préfixe (`!`), dédup, max ~10 alias × 32 car., regex autorisée (lettres/chiffres/`_-`), **`{$t:...}` supporté** comme pour le nom ;
   - ajout dans l'allow-list `normalize_command_data.dart` (+ round-trip), `logic/command_editor_state.dart` + `command_editor_notifier.dart` (`updateAliases`), écriture `command.create.serialization.dart`.
2. **UI** :
   - `scratch_blocks/entry_point_block.dart` (section Legacy) : champ **chips** « Alias » (ajout Entrée/virgule, suppression croix, refus des doublons, aide « même commande déclenchée par plusieurs mots ») ; afficher `!commande, !alias…` dans le titre du bloc ;
   - `metadata_block.dart` / `command.create.wizard.dart` : même source de vérité (pas de 2ᵉ formulaire) ;
   - `commands.list.dart` : chips d'alias sur la carte + **recherche par alias** ;
   - i18n : `command_alias_label`, `_hint`, `_help`, `_duplicate`, `_limit` × **6 langues**.
3. **Moteur** (`event_dispatcher.dart`) :
   - extraire un helper `legacyCommandTriggerNames(command)` = nom nettoyé + alias nettoyés (`cleanCommandTriggerName` appliqué partout, `{$t}` compris) ;
   - matcher **exact** (pas de préfixe), insensible à la casse ; priorité au nom ; **collision** = première commande déclarée (documenté) + avertissement dans l'UI quand un alias est déjà utilisé par une autre commande du bot ;
   - `/help` intégré (l.687+) : afficher les alias disponibles ;
   - `$awaitedCommand[...]` et les commandes slash : hors périmètre (vérifier qu'aucun code n'impose « 1 seul trigger » ailleurs, ex. `application_intent_sync.dart`).
4. **Docs** : `docs/command-format.md` (section `aliases` dans `data`) + vitrine `_docs` (EN) sur la commande Message Texte.
