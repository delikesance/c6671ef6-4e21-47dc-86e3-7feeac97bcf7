# Native interaction callback queries

Official sources checked on 2026-10-04: [$customID](https://wiki.botdesignerdiscord.com/bdscript/customID.html), the [select-menu guide](https://wiki.botdesignerdiscord.com/guides/general/interactions/selectMenus/aboutSelectMenu.html), and the [official changelog](https://wiki.botdesignerdiscord.com/CHANGELOG.html).

customID takes zero arguments and returns the custom ID of the interaction callback. The event adapter exposes the actual Discord interaction type as `interaction.type`; the native binding accepts component (3) and modal-submit (5) contexts carrying a populated `interaction.customId`. It rejects missing IDs and ordinary message, slash-command or autocomplete contexts instead of substituting command options or message content. The wiki names the `$onInteraction` callback; accepting modal-submit callbacks is a local mapping to the existing event adapter, not independently verified backend behavior. Returned IDs remain literal data, including dollar signs and brackets.

No official parameter contracts could be retrieved for getStringSelectValue/getStringSelectValues, getUserSelectUserID/getUserSelectUserIDs, getRoleSelectRoleID/getRoleSelectRoleIDs, getChannelSelectChannelID/getChannelSelectChannelIDs or getMentionableSelectUserID/getMentionableSelectUserIDs. Their stable `/bdscript/` and nightly pages were unavailable, as were tested `/functions/` paths. The official wiki source checkout contains no corresponding function pages. The changelog confirms several names but does not define their indexing, separator, scope or missing-value behavior. The guide explains legacy selection through `$message`, without these getter contracts. Therefore this migration does not register speculative native handlers or infer their signatures from the local legacy resolver. Existing editor hints and legacy behavior do not establish official parity.

The existing select-variable extraction uses textual component-type names. Actual nyxx ComponentType objects do not necessarily stringify to those names, so selector-specific aliases require a separate adapter correction before depending on them. General interaction values and custom IDs remain available. This batch only adds the numeric interaction type field.

Eight dedicated tests cover component and modal event data, selection ID versus option values, native Sandbox output, literal values, rejected non-callback contexts, missing metadata, arity preflight before effects and unknown opaque arguments. Existing interaction-event tests also run. No Discord requests are made.
