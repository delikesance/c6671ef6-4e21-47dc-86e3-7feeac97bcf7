# Native custom functions and error policies

Sources inspected on 2026-10-04:

- Official wiki: [$suppressErrors](https://wiki.botdesignerdiscord.com/bdscript/suppressErrors.html), [$embedSuppressErrors](https://wiki.botdesignerdiscord.com/bdscript/embedSuppressErrors.html), [$unescape](https://wiki.botdesignerdiscord.com/bdscript/unescape.html), [$removeLinks](https://wiki.botdesignerdiscord.com/bdscript/removeLinks.html), [$removeContains](https://wiki.botdesignerdiscord.com/bdscript/removeContains.html), [$awaitFunc](https://wiki.botdesignerdiscord.com/bdscript/awaitFunc.html).
- Official [changelog](https://wiki.botdesignerdiscord.com/CHANGELOG.html) confirms the optional custom suppression response and `$suppressErrorLogging`. A dedicated logging page was unavailable.
- Repository-owned `vitrine/_docs/func.md`, `funcarg.md`, `funccall.md`, `funcend.md`, `funcreturn.md` and the existing transpiler implementation. These five functions are Bot Creator extensions; corresponding official wiki and repository pages were unavailable. Their contracts must not be presented as official BDFD semantics.

`$func[name;parameters...] ... $funcEnd` now forms an AST statement. Names and parameter names are literal, nonempty, case-insensitive identifiers. Definitions emit nothing and register when encountered, so a call requires an earlier executed definition. The body is validated before command effects, including unused definitions, but runs only at `$funcCall`. Nested definitions exist within their calling function and are restored on exit.

Arguments are evaluated once in the caller's scope. Missing declared arguments use empty strings; surplus arguments are left unevaluated, matching the old extension. Values are data, including dollar syntax, and never reparsed. `$funcArg` outside a call returns empty. Body text is returned at the call site without being separately appended to the response. Effects execute when the function is called. `$funcReturn` records a return value; the last executed return wins, matching the existing transpiler and the specific funcReturn documentation. The general func page's suggestion of early return is inconsistent with this existing behavior and is not adopted. Undefined calls and calls beyond ten custom frames return empty with a diagnostic trace event. Structural nesting, generic function nesting, execution steps and the shared deadline remain independently bounded.

`$suppressErrors` hides runtime error responses; its optional string replaces them. Errors abort remaining statements without rolling back earlier effects. Native guards with error messages use the configured response. A plain `$stop` keeps its existing control semantics. `$try` gets the first opportunity to catch runtime errors. Shared timeouts remain errors and cannot be suppressed. Suppression applies to native service failures and final response flush failures; only the replacement response is attempted after a failed send, never the original draft again.

`$embedSuppressErrors[title;description;(color;author;footer;footer icon)]` validates its fields and replaces a failed draft with the configured embed. An empty description uses the original guard/runtime message. The message adapter implements `BdfdErrorOutput` to apply the replacement. Without a compatible output, execution reports the missing output capability rather than silently dropping the embed. Color accepts a `#` hex value or integer; footer URLs require HTTP(S). Discord field-size checks remain in the message output service.

`$suppressErrorLogging` sets invocation-local `context.suppressErrorLogging`; host error logging must respect it. It does not suppress runtime failures or diagnostic traces. Custom definitions, response policies, logging suppression and link filtering reset at the start of each top-level invocation, while nested execution shares them.

`$removeLinks` marks the reply for HTTP(S) URL removal, including text accumulated before the directive. The native runtime filters its returned reply and the message adapter filters the final draft. This intentionally does not claim to strip every bare domain or modify arbitrary explicit message-service requests.

`$unescape[text]` remains data at top level. `BdfdInvocation.expandedArguments()` interprets semicolons only from direct `$unescape` expressions as argument boundaries. Plain runtime variables with semicolons stay one argument. Expansion never interprets dollar syntax, and both expanded and ordinary argument access share evaluation caches. The random-text adapter consumes this expansion explicitly; functions without an audited dynamic-tuple contract retain their ordinary argument rules.

`$removeContains` is a Discord message purge operation, not string removal. `$awaitFunc` registers an awaited command, not a call to a custom function. Neither is registered by this change: message history/filter deletion and an awaited-command event consumer require complete service and dispatcher implementations. The previous transpiler's await registration alone is insufficient evidence of supported awaited execution.

Validation: `bdfd_native_language_test.dart` covers custom scope, lazy bodies, once-only arguments, unknown opaque calls, bounded recursion, return behavior, policies, embeds, failed flushes, cancellation, invocation isolation and unescape data safety. Additional native engine, loop and validation tests verify compatibility. No Discord requests are made by these tests.
